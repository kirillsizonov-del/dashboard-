# Как склонировать дашборд под другую команду

Инструкция для копии TRAFIC под новую команду, например SMM quadcode.ai. Сначала устройство, потом шаги по порядку, потом карта: какой файл править, чтобы поменять каналы, этапы и правила.

Пути ниже даны по ветке `main` на GitHub. В ней дашборд открывается на `/`, страницы лежат прямо в `src/app/`.

## 1. Что это

Командный дашборд без входа по паролю. Разделы:
- **Обзор:** что делать сейчас, статус каналов, цель недели.
- **Задачи:** канбан на три колонки.
- **Каналы:** списки целей с этапами воронки.
- **Документы:** тексты, отчёты, выгрузки.
- **Аналитика:** графики по журналу действий.
- **КП:** конструктор коммерческого предложения. Он нужен только TRAFIC, в копии его удаляем.

Все участники видят изменения друг друга сразу, через Supabase Realtime.

**Стек:** Next.js 16 (App Router, Turbopack), React 19, TypeScript, Tailwind 4, lucide-react, simple-icons для логотипов соцсетей, `@supabase/supabase-js`. Сервера своего нет: всё работает в браузере, база Supabase, хостинг Vercel.

> В этой версии Next.js есть ломающие изменения. Перед правками кода прочитайте `AGENTS.md` и нужный раздел в `node_modules/next/dist/docs/`.

## 2. Как устроено

### Данные: одна таблица на всё

`supabase/schema.sql` создаёт таблицу `items`:

| колонка | что хранит |
|---|---|
| `workspace` | имя рабочего пространства, из `NEXT_PUBLIC_WORKSPACE` |
| `kind` | `member`, `channel`, `target`, `task`, `event`, `doc` или `meta` |
| `id` | id записи |
| `data` | сама запись в jsonb, форма из `src/lib/types.ts` |
| `deleted` | удалена ли запись. Удаление мягкое: строка остаётся с `deleted=true` |
| `updated_at` | время изменения |

Первичный ключ `(workspace, kind, id)`. Запись идёт upsert с `on_conflict=workspace,kind,id`. Новый тип данных не требует миграций: достаточно нового `kind` в коде.

### Поток данных

```
UI → действие из store.ts → commit(rows) → applyRows (локально, сразу)
                                          → backend.save(rows) (в фоне)
Supabase Realtime → backend.subscribe → applyRows → все открытые вкладки
```

- `src/lib/store.ts`: состояние и все действия. Компоненты читают состояние через `useApp()` (`useSyncExternalStore`) и вызывают экспортированные функции: `addTask`, `moveTask`, `touchTarget`, `setStage`, `saveDoc` и другие. Напрямую в базу никто не пишет.
- `src/lib/backend.ts`: интерфейс хранилища и перевод строк в объект `DB` и обратно.
- `src/lib/backend-supabase.ts`: общая база. Загружает страницами по 1000 строк и подписан на Realtime.
- `src/lib/backend-local.ts`: запасной вариант, всё хранится в localStorage этого браузера. Включается, если Supabase недоступен или задано `NEXT_PUBLIC_SUPABASE_URL=off`.
- `src/lib/config.ts`: адрес базы, ключ и workspace. **По умолчанию там вшита база TRAFIC.** В копии эти значения нужно заменить первым делом (шаг 3).

### Журнал действий

Каждое действие пишет запись `event` (`EvType` в `types.ts`): задачу добавили, взяли в работу или закрыли, ежедневную отметили, написали цели, сменился этап воронки и так далее. Всю аналитику (`src/lib/analytics.ts`) и недельный отчёт (`buildReport` в `src/lib/exporter.ts`) считаем по журналу, а не по текущему состоянию. Отсюда правило: новое действие в store всегда пишет `ev(...)`, иначе его не будет на графиках.

### Кто я

Участник выбирает себя в настройках, выбор хранится в localStorage этого браузера (`pult:v1:me`). От этого зависят подпись в журнале и правило «кто перетащил карточку в "В работе", тот её и взял» (`claim()` в `store.ts`).

### Стартовые данные

`src/lib/seed.ts` загружается **один раз**, когда в workspace нет ни одной строки. Там участники, каналы, цели и задачи TRAFIC. Если не почистить файл до первого запуска, копия начнёт со списков лидов TRAFIC.

### Автоотчёт

При первом открытии дашборда на неделе в «Документы» сам сохраняется отчёт за прошлую неделю (`autoWeeklyReport` в `store.ts`). Id отчёта зависит только от недели, поэтому два браузера не создадут дубль.

## 3. Клонирование по шагам

### 3.1 Код

```bash
git clone git@github.com:developerduhreserv/dashboardDD.git smm-dashboard
```

```bash
cd smm-dashboard && rm -rf .git && git init && npm install
```

### 3.2 Своя база Supabase

Нужен **отдельный проект Supabase**, не новый workspace в базе TRAFIC. Правила доступа в схеме открыты всем, у кого есть публичный ключ. В общей базе SMM-команда технически сможет читать и править данные TRAFIC, а TRAFIC её данные.

1. Создайте проект на supabase.com. Регион ближе к команде, для Европы и Грузии подойдёт Frankfurt.
2. SQL Editor → New query → вставьте `supabase/schema.sql` → Run. Скрипт создаёт таблицу, правила доступа и включает Realtime.
3. Project Settings → API: скопируйте URL проекта и **publishable** ключ (`sb_publishable_...`). Секретный ключ дашборду не нужен, никуда его не кладите.

### 3.3 Конфиг

Замените значения по умолчанию в `src/lib/config.ts` на свои. Иначе любая сборка без переменных окружения будет писать в базу TRAFIC.

```ts
export const SUPABASE_URL = process.env.NEXT_PUBLIC_SUPABASE_URL || "https://<ваш-проект>.supabase.co";
export const SUPABASE_KEY = process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY || "sb_publishable_<ваш ключ>";
export const WORKSPACE = process.env.NEXT_PUBLIC_WORKSPACE || "main";
```

Поправьте и `.env.example`. Переменные `NEXT_PUBLIC_*` вшиваются в сборку, поэтому после их смены на Vercel нужен новый деплой.

### 3.4 Стартовые данные

В `src/lib/seed.ts`:
- `MEMBERS`: участники новой команды. Id вида `m-anna`, цвета берите из `MEMBER_COLORS` в `meta.ts`.
- `CHANNELS`: каналы новой команды (раздел 4.1).
- массивы `TG`, `IG`, `TASKS`: очистите или заполните своими. Вместе с ними удалите циклы `TG.forEach` и `IG.forEach` в `seedRows()` и импорт `IG_MESSAGES`.
- `meta`: имя workspace (`"TRAFIC"` → например `"SMM"`) и `funnelGoal`, недельные цели воронки. Встречается дважды: в `emptyDB()` и в `seedRows()`.

`src/lib/seed-messages.ts` (тексты для лидов в Instagram) удалите.

### 3.5 Названия и вид

- `README.md`, `metadata` в `src/app/layout.tsx` (title и description): название дашборда.
- `Logo` в `src/components/ui.tsx`: значок в шапке.
- Цвета и шрифты в `src/app/globals.css`: акцент `--accent`, цвета каналов `--c-*`. Кириллицу держат Geologica и Inter, заголовочный Lexend с кириллицей не работает.

### 3.6 Запуск и деплой

```bash
npm run dev
```

Откройте http://localhost:3000. При первом открытии seed запишется в новую базу. Выберите себя в настройках (шестерёнка в шапке).

Перед пушем:

```bash
npm run lint && npm run build
```

Деплой: новый репозиторий на GitHub → Vercel → Add New Project → Import. Переменные можно не задавать, если значения вшиты в `config.ts`. После этого каждый пуш в `main` собирается сам.

## 4. Карта адаптации: что где менять

### 4.1 Каналы

Набор каналов задан списком id, и от него зависит много мест. Чтобы добавить канал (например `tiktok`, `youtube`, `linkedin`, `x`) или убрать лишний, правьте все места сразу. Иначе TypeScript не соберёт проект, и это хорошо: компилятор покажет, что забыто.

| файл | что поменять |
|---|---|
| `src/lib/types.ts` | `CHANNEL_IDS`: список id. Отсюда выводится тип `ChannelId` |
| `src/lib/meta.ts` | `CHANNELS`: название, цвет, как называются цели и касания в трёх формах множественного числа («аккаунт, аккаунта, аккаунтов»), глагол касания для журнала («Написали», «Запостили») |
| `src/app/globals.css` | переменная цвета `--c-<id>` в `:root` |
| `src/components/ui.tsx` | `ICON_PATH`: иконка из `simple-icons` (`siTiktok`, `siYoutube` и т. п.). Каналу без логотипа дайте иконку lucide, как у `warm` в `ChannelIcon` |
| `src/lib/parse.ts` | `ALIASES` и `KEYWORDS`: какие метки в быстром вводе означают канал (`#тикток`, `#ютуб`) |
| `src/lib/importer.ts` | домены ссылок → канал (первый список в файле) и слова в колонке «канал» CSV → канал (`CHANNEL_WORDS`). Плюс как строить ссылку из ника (`fromLink`, `fromHandle`) |
| `src/lib/seed.ts` | `CHANNELS`: стартовый статус, аккаунт, дневная цель и заметка по каждому каналу |
| `src/app/channels/page.tsx` | канал, который открывается по `/channels` (сейчас `telegram`) |

Аналитика (`SERIES` в `analytics.ts`), фильтры и списки строятся из `CHANNEL_IDS` сами.

### 4.2 Этапы воронки

Сейчас воронка продажи сайтов: `new → sent → replied → concept → call → won`, плюс `lost`.

| файл | что поменять |
|---|---|
| `src/lib/types.ts` | `STAGES` (все этапы) и `FUNNEL_STAGES` (те, что считаются в воронке, по порядку) |
| `src/lib/meta.ts` | `STAGE_LABEL` и `FUNNEL_LABEL`: подписи |
| `src/lib/seed.ts` | `funnelGoal` в `emptyDB()` и `seedRows()`: ключи должны совпадать с `FUNNEL_STAGES` |
| `src/lib/store.ts` | `touchTarget` и `setStage`: какой этап ставится после первого касания (сейчас `sent`) |

### 4.3 Задачи

- Статусы колонок: `TaskStatus` в `types.ts` и `TASK_STATUS_LABEL` в `meta.ts`.
- Приоритеты: `PRIORITY_LABEL` в `meta.ts`.
- **Ежедневные обязательные задачи** (закреп сверху с кнопкой «Выполнено» и серией дней, `src/components/daily.tsx`) задаются данными, а не кодом. Создайте задачу и в редакторе включите «Повтор → Каждый день, в закреп». Для SMM это, например, «Сторис в Instagram», «Пост в Threads», «Ответить на комментарии».
- Сортировка открытых задач: по сроку, ближайшие сверху (`byDue` в `src/components/tasks.tsx`).

### 4.4 Правила TRAFIC, которые в копии убрать

| где | что это |
|---|---|
| `src/lib/store.ts`, `claim()` и `taskRows()` | задачи канала `vk` всегда достаются `m-colleague` (Максиму). Удалите обе проверки на `"vk"` |
| `src/components/ChannelView.tsx`, около строки 369 | кнопка «текст сообщения» показывается у всех целей Instagram. Оставьте условие только `t.message` или привяжите к своему каналу |
| `src/components/kp.tsx`, `src/app/kp/page.tsx`, пункт «КП» в `NAV` в `src/components/AppShell.tsx`, блок `@media print` в `globals.css` | конструктор КП для продажи сайтов. Удалите целиком |
| `src/lib/seed-messages.ts` | тексты для лидов TRAFIC |

### 4.5 Что значит «цель» для SMM

В TRAFIC цель (`Target`) означает чат или аккаунт, которому пишем. Касание (`touchTarget`) означает «написали или запостили». Для SMM подойдут два варианта.

- **Цели как аккаунты для коллабораций и посева:** блогеры, паблики, чаты. Тогда модель подходит как есть, меняются только каналы и этапы, например `new → sent → replied → agreed → published`.
- **Цели как единицы контента:** пост, рилс, видео. Тогда этапы `idea → draft → review → scheduled → published`, касание считаем как «опубликовали», а в `note` пишем ссылку на макет. В `meta.ts` поменяйте формы слов: `target: ["пост", "поста", "постов"]`, `touchVerb: "Опубликовали"`.

Если нужны оба варианта сразу, заведите второй тип записей через новый `kind`. Его надо добавить в `Kind` в `types.ts`, в `KEY` в `backend.ts` и в `DB`, плюс написать действия в `store.ts`. Таблица в базе не меняется.

## 5. Безопасность

- Правила в `schema.sql` открыты: читать и менять данные может любой, у кого есть ссылка на дашборд, потому что публичный ключ уходит в браузер. Для внутреннего дашборда компании этого мало.
- Как закрыть по-простому: включить Vercel Authentication (Settings → Deployment Protection) на продакшен-домен, тогда открыть дашборд смогут только участники команды на Vercel. База при этом остаётся доступной по ключу, но ключ видят только они.
- Как правильно: Supabase Auth, вход по почте только с доменом `@quadcode.ai`. Правила в `schema.sql` переписать на проверку `auth.uid()` или `auth.jwt() ->> 'email'`. В `backend-supabase.ts` передавать сессию.
- Секретный ключ (`sb_secret_...`) в код и в переменные `NEXT_PUBLIC_*` не кладём никогда.

## 6. Подводные камни

- **Seed пишется, только когда workspace пустой.** Чтобы перезалить стартовые данные, есть «Сбросить к исходным» в настройках (`resetToSeed`) или удаление строк workspace в Supabase.
- **Выгрузка и загрузка всего workspace:** в настройках есть экспорт и импорт JSON (`exportJSON` и `importJSON`). Так удобно переносить данные между базами.
- **Документ до 900 КБ** (`DOC_LIMIT` в `store.ts`): хранится текстом в jsonb.
- **Ключи localStorage** начинаются с `pult:v1:`. Если открыть две копии дашборда на одном домене (например localhost), они будут делить выбор «кто я» и локальную базу. Разные домены друг другу не мешают.
- **Удаление мягкое:** строка остаётся в таблице с `deleted=true`. Если нужно, чистите вручную.
- **Realtime** работает, только если таблица добавлена в публикацию `supabase_realtime`. Это последняя строка `schema.sql`. Если изменения не прилетают другим, сначала проверьте это.

## 7. Чеклист копии

- [ ] Новый репозиторий, `.git` от TRAFIC удалён
- [ ] Отдельный проект Supabase, `schema.sql` выполнен
- [ ] `src/lib/config.ts` и `.env.example` указывают на новую базу
- [ ] `seed.ts` очищен: свои участники и каналы, без лидов TRAFIC, `seed-messages.ts` удалён
- [ ] Каналы заменены во всех местах из раздела 4.1, `npm run build` проходит
- [ ] Этапы и цели воронки под SMM (раздел 4.2)
- [ ] Правило про `vk`, кнопка текста для Instagram и КП удалены (раздел 4.4)
- [ ] Название, лого и акцент в шапке и `metadata`
- [ ] Ежедневные задачи созданы через «Повтор»
- [ ] Vercel подключён, доступ закрыт (раздел 5)

## 8. Готовый запрос для Claude в новом проекте

Скопируйте в новую сессию, открытую в папке копии:

```
Это копия командного дашборда TRAFIC. Прочитай docs/CLONE.md и AGENTS.md.
Адаптируй его под SMM-команду quadcode.ai:
- участники: [имена]
- каналы: [например Instagram, TikTok, YouTube, LinkedIn, X, Threads]
- цель = [аккаунт для посева / единица контента], этапы: [список]
- ежедневные задачи: [список]
- новый Supabase: URL [..], publishable key [..]
Пройди чеклист из раздела 7, убери всё про продажу сайтов, собери и проверь npm run build.
```
